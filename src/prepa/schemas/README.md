# Общие форматы данных

`content.py` содержит реализованные Pydantic-контракты, общие для всех участников,
независимые от Telegram, БД, LLM-провайдера и LaTeX. Поля, ограничения и примеры API:
[контракт и интеграция](../../../docs/content-agents.md).

Вход: `GenerationContext(brief, students, materials)`; содержание: `Theory` и
`AssignmentSet`; ответ модели reviewer: `ReviewReport`; проверка, привязанная кодом
к точным данным: `ReviewResult`. Явный отказ по недостатку материалов:
`GenerationFailure`. Локальные замечания к отклонённой генерации: `RepairFeedback`.
Комплект создаётся через `LessonPackage`, ученический вход — `package.for_student(id)`.

Модели неизменяемы, лишние поля запрещены. Python использует tuples, JSON — arrays.
Читать через `model_validate`/`model_validate_json`, писать через
`model_dump(mode="json")`/`model_dump_json`; JSON Schema — `model_json_schema()`.
После изменения валидировать новую модель: `model_copy(update=...)` не проверяет
значения и не подходит для принятия внешних правок.

`validation.py` проверяет идентичность/версию, темы, ссылки, покрытие, объём, время,
адреса замечаний и digest. Это структурные проверки, не доказательство физики.
`approved` — Python property по отсутствию error, не JSON-поле. Warning не блокирует.

`for_student` исключает ответы/решения/подсказки практики, чужое ДЗ, профили и сырые
материалы. Разобранные примеры теории сохраняют решения намеренно. `TextBlock.text`
нужно безопасно экранировать; `math` содержит выражения, не готовый документ.

Схемы меняются общим PR с JSON до/после, миграцией, тестами и обновлением промптов/demo;
затронутые участники проверяют адаптеры. Не создавать копии моделей в своих модулях.
brief.version — версия подготовки, не формата схемы. Результат PDF согласуют отдельно
участники 1 и 3.
