# Проверки слоя содержания

Тесты выполняются без Telegram, базы, провайдера LLM и TeX. После создания окружения
Python 3.12+ и установки `python -m pip install -e '.[dev]'` из корня репозитория:

```bash
python -m pytest
python -m pytest --cov=prepa --cov-report=term-missing
python -m ruff check .
python -m mypy src/prepa
python -m build
python examples/content_agents.py --output-dir output/content-demo
```

| Модуль | Назначение |
|---|---|
| test_schemas.py | JSON roundtrip, closed/frozen модели, строгие значения и пределы коллекций, ID, brief/profiles/materials, GenerationFailure/RepairFeedback, ученическая проекция |
| test_quality.py | Темы/источники/покрытие/число/время, нулевое ДЗ, адреса review, package gates, warnings, digest и устаревшие данные |
| test_agents.py | Структурированный вызов и JSON, отказ/таймаут/отмена/ошибки провайдера, подтверждение до LLM, предел ответа, адресованные исправления, сохранение локальных ошибок и свежая проверка комплекта |

Тесты агента используют записанные ответы подменного StructuredLLM: они подтверждают
передачу схемы, обработку ошибок и поведение API, а не правильность физики живой LLM.
Большой процент покрытия кода не является предметной оценкой.

Проекция проверяется по контексту: ответы/решения/подсказки практики и ДЗ исключены,
как и чужое ДЗ, профили, rationale и raw Material.content. Разобранные примеры теории
намеренно содержат решения. Для digest проверяются изменения theory, assignments,
brief, профиля и источников, а не только смена version.

Для нового поведения добавлять граничный сценарий и конкретную регрессию; изменение
общего формата сопровождать обновлением demo, промптов и документации. Не добавлять
зависимость unit-тестов от сети/ключей. Живое сравнение моделей и физический rubric
описаны в [качестве](../docs/content-quality.md); end-to-end Telegram/PDF появятся
вместе с реализацией соответствующих модулей.
