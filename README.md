# Prepa

ИИ-помощник репетитора по физике для подготовки учеников 9–11 классов к ОГЭ и ЕГЭ.

Prepa помогает готовить занятия для учеников разного уровня: учитывает их историю, подбирает учебные материалы, составляет план параллельного урока и индивидуальные домашние задания.

## Статус проекта

Проект находится на этапе проектирования. Работающего приложения, Dockerfile и конфигурации Docker Compose пока нет. Описанные ниже возможности и технологии — план реализации.

## Основной сценарий

1. Репетитор выбирает двух учеников и задаёт тему, длительность занятия и ограничения.
2. Система получает профили учеников: цели, пройденные темы, результаты и типичные ошибки.
3. Подбирает подходящие материалы из проверенной библиотеки.
4. Составляет общее расписание урока с чередованием работы с преподавателем и самостоятельной работы.
5. Готовит индивидуальные задания и ДЗ, источники, ответы и решения для преподавателя.
6. Репетитор проверяет и редактирует результат.
7. После занятия фактические результаты сохраняются и учитываются при следующей подготовке.

Пример запроса:

> Подготовь занятие на 60 минут по кинематике для двух учеников. У ученика А трудности с переводом величин в СИ, ученик Б уверенно решает базовые задачи. Подготовь отдельное ДЗ примерно на 20 минут каждому.

## Планируемый MVP

- Профили учеников с указанием экзамена, цели, освоенных тем и ошибок.
- Библиотека проверенных задач по выбранному разделу физики.
- Подбор материалов с указанием источников.
- План параллельного урока для двух учеников.
- Индивидуальные домашние задания.
- Проверка и редактирование результата репетитором.
- Сохранение истории занятий и прогресса.

Начальный раздел физики предстоит выбрать команде. Долгосрочная учебная траектория и её корректировка по прогрессу — следующий этап развития.

## Предлагаемая архитектура

| Компонент | Ответственность |
|---|---|
| Координатор | Обработка запроса и запуск этапов подготовки |
| Модуль ученика и прогресса | Хранение истории, анализ пробелов, предложение следующего шага |
| Агент подбора материалов | Поиск и отбор материалов под тему и уровень |
| Агент занятия и ДЗ | План урока и индивидуальные задания |
| Проверки результата | Формат, источники, временные ограничения и замечания к качеству |

Агенты — логические роли внутри одного серверного приложения. Они могут использовать одну модель с разными инструкциями. Окончательное решение о применении материалов принимает преподаватель.

## Предлагаемые технологии

- Python и FastAPI — сервер, доступ к данным и агентам.
- Streamlit — интерфейс репетитора.
- PostgreSQL — профили, материалы, планы и история.
- OpenRouter — вызов LLM по API. Модель работает у внешнего провайдера.
- Docker Compose — совместный запуск интерфейса, сервера и базы.
- pgvector и embedding-модель — при добавлении поиска по смыслу.
- LangGraph — при необходимости ветвления, повторных проверок и управления состоянием.

Конкретные модели будут выбраны после сравнения на примерах по физике. Для демо используются вымышленные профили учеников. API-ключи хранятся в локальном `.env` и не публикуются.

## Команда и распределение работы

Команда состоит из четырёх человек. ФИО и GitHub-ники остальных участников предстоит добавить.

| Участник | Зона ответственности |
|---|---|
| Руководитель: [sukis222](https://github.com/sukis222), ФИО предстоит добавить | Предметные критерии, интерфейс, интеграция, Docker и общий результат |
| Участник 2 — предстоит указать | Профили, история, прогресс и учебная траектория |
| Участник 3 — предстоит указать | Библиотека материалов, разметка и поиск |
| Участник 4 — предстоит указать | План урока, ДЗ и проверки качества |

Перед параллельной разработкой команда согласует форматы `StudentProfile`, `LearningPlan`, `Material`, `LessonRequest` и `LessonPackage`. Изменения выполняются в отдельных ветках и объединяются через pull request.

## Запуск

Запуск приложения пока недоступен. После реализации здесь будут точные инструкции: создание `.env` из `.env.example`, подготовка базы и демоданных, запуск через Docker Compose и адрес интерфейса.

## Проверка результата

- Правильность физических условий, ответов, единиц измерения и решений.
- Соответствие заданий уровню ученика и цели занятия.
- Реальные источники выбранных материалов.
- Согласованное расписание работы преподавателя с двумя учениками.
- Время подготовки с учётом проверки и правок.
- Учёт результатов предыдущего занятия.

Экономия времени и качество относительно ручной подготовки пока являются гипотезами и требуют проверки.
