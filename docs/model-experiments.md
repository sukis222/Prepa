# Какие бесплатные модели проверяли

Срез экспериментов: 23 октября 2026 года. Это история проверок, а не рейтинг
актуальной доступности OpenRouter. Все перечисленные ID оканчиваются на `:free`.
Нулевой тариф проверялся по каталогу; в успешных сохранённых ответах API указан
`cost: 0`. Количество прогонов небольшое, поэтому проценты надёжности и выводы
«лучшая модель по физике» из этих результатов делать нельзя.

## Краткий текст для слайда

**Заголовок: «Выбор бесплатной модели для MVP»**

- Сравнили пять моделей на одинаковой задаче: выбрать четыре задачи по термодинамике из шести готовых условий и вернуть JSON с ID.
- **Dots 3 Note Preview — текущая текстовая модель:** корректный JSON, 6,1 с в основном прогоне; затем проверена в полном сценарии «источник → отбор → PDF».
- **Nemotron 3.5 Super VL — рабочая альтернатива:** корректный результат за 3,1 с; оставлена кандидатом для распознавания решений по изображениям. По этому тесту не хуже Dots и быстрее неё.
- **Xing 4.0 — резервный кандидат:** сначала некорректный ответ; с другими параметрами успешно за 7,3 с; при следующем запросе ограничение частоты.
- **Liquid LFM 2.5 — работает, но медленнее в этих прогонах:** обязательный reasoning; 62,9 и 83,6 с.
- **Nemotron 3 Super 120B — не выбран из-за доступности:** `model_unavailable`, увеличение таймаута не помогло.
- Текущие настройки Dots: `temperature=0.2`, `max_tokens=4096`, reasoning выключен, HTTP-таймаут 120 с. Модель выбирает ID; исходные условия и рисунки переносит код.

Подпись мелким шрифтом: «Одиночные технические прогоны, не доказательство
предметного превосходства. Пять моделей, четыре с успешным отбором».

## Что именно сравнивали

Основной сопоставимый тест использовал существующий PDF/набор Prepa: четыре задачи
по термодинамике и две по движению. Это ранее составленные и затем исправленные
задачи Prepa, **не оригинальный банк ФИПИ**. Модели требовалось выбрать четыре
подходящих ID. Новые условия, решения и изображения в этом тесте не генерировались.

Для сравнений сохранены одинаковые хеши набора, пользовательского запроса,
системного запроса и JSON-схемы. Последние два хеша были восстановлены после
прогона из фиксированных констант скрипта; хеши набора и пользовательского запроса
записывались при запуске. Корпус:
`66f34e630e2032742c43f565bb00e26b68a17e74ff78e83b99c9bdb1c6514b84`.

Проверяли корректность ID, их уникальность, количество, попадание в требуемую
тему и принятие структурированного ответа. Дословность условий обеспечивал код,
а не обещание модели. Для четырёх успешных моделей и одного варианта параметров
Dots собрали пять отдельных PDF и проверили сохранение исходных условий.
Это не проверка решения сложной физики, качества рукописного OCR или анализа графиков.

## Результаты основного теста

Время ниже — один измеренный inference, без предварительной проверки каталога.
Общие настройки: `temperature=0.2`, `max_tokens=4096`, reasoning `off`, HTTP-таймаут
60 с; исключения указаны в таблице. Полное время и сетевые ограничения могут
отличаться от этого значения.

| Модель | Параметры / вариант | Наблюдаемый результат | Решение для MVP |
| --- | --- | --- | --- |
| `dots-studio/dots-3-note-preview:free` | Общие | 4 корректных ID; 6,103 с; 243 выходных токена | Текущий текстовый отбор; предметное превосходство не установлено |
| Dots, второй вариант | temperature 0; max_tokens 2048; reasoning off | 4 корректных ID; 9,016 с; 218 выходных токенов | Альтернативные настройки работают; оснований считать их лучше нет |
| `nvidia/nemotron-3.5-super-vl:free` | Общие | 4 корректных ID; 3,085 с; 184 выходных токена | Рабочая альтернатива; в этом прогоне быстрее Dots |
| `xingchen-agi/xing4.0-29b-a4b:free` | Общие | `invalid_response`; 9,512 с полного запроса | Не выбран настройкой по умолчанию |
| Xing, явный повтор с изменением параметров | temperature 0; max_tokens 2048; reasoning off | 4 корректных ID; 7,345 с; 225 выходных токенов | Рабочий резервный кандидат; это не повтор с теми же параметрами |
| `liquid/lfm-2.5-2.6b:free` | temperature 0.2; max_tokens 4096; reasoning default | 4 корректных ID; 62,906 с; 603 выходных токена, из них 419 reasoning | Корректно, но медленнее в измеренных прогонах |
| `nvidia/nemotron-3-super-120b-a12b:free` | Общие | `model_unavailable`; 0,804 с полного запроса | Нельзя оценить качество: запрос не получил доступного исполнения |

Liquid нельзя напрямую сравнивать по режиму reasoning с остальными: у неё
reasoning обязателен. Первый запуск помощника ошибочно сохранил `off`, хотя CLI
просил `default`; preflight остановил его **до inference** с
`reasoning_configuration_unavailable`. Это ошибка настройки эксперимента, не
ошибка решения модели. После исправления Liquid успешно прошла тест.

Также 60 секунд — настройка HTTP, а не гарантия общего wall-clock времени:
скрипт имел внешний предел на 15 секунд больше. Поэтому успешный inference
Liquid 62,906 с не следует переписывать в «таймаут на 60 с».

## Повторная проверка после увеличения таймаута до 120 секунд

Использован тот же набор и запрос; внешний предел скрипта — 135 с.

| Модель | Параметры | Результат |
| --- | --- | --- |
| Liquid LFM 2.5 | temperature 0.2; max_tokens 4096; reasoning default | Успех, 4 корректных ID; inference 83,601 с; 717 выходных токенов, из них 496 reasoning; cost 0 |
| Xing 4.0 | temperature 0; max_tokens 2048; reasoning off | `rate_limit` за 0,514 с inference; длинный таймаут не устраняет ограничение частоты |
| Nemotron 3 Super 120B | temperature 0.2; max_tokens 4096; reasoning off | `model_unavailable` за 0,389 с inference; длинный таймаут не создаёт доступного провайдера |

В сохранённых основных сравнительных результатах нет доказательства, что Xing
или 120B падали именно из-за 60-секундного таймаута: причины были другими.
Не надо описывать их как «модели, исправленные увеличением таймаута».

## Почему оставили Dots

Это практический выбор уже интегрированного текстового варианта, а не победа в
статистическом конкурсе. Dots прошла JSON-контракт в двух настройках и дальнейшие
полные проверки с реальным источником «Решай Онлайн». Сохранены успешные
сквозные результаты для 20 задач по термодинамике, четырёх задач с циклами и
30 задач по магнетизму. Эти проверки включали сохранение результата и сборку PDF;
сами итоговые отчёты не содержат отдельной сравнительной оценки моделей.

Текущий профиль — temperature 0.2, max_tokens 4096, reasoning off, HTTP-таймаут
120 с. Настройки ограничивают размер и режим ответа; они не доказаны оптимальными.
Модель получает исходные кандидаты и возвращает ID. Точность копирования,
рисунки и типографика — ответственность парсера, валидатора и модуля документов.
Имена учеников модели не нужны и не передаются.

**Nemotron VL не была отклонена из-за плохого качества:** она успешно прошла тот
же тест и была быстрее в одиночном измерении. Для выбора между ней и Dots по
надёжности нужна серия одинаковых запросов на разных темах, подсчёт корректных
отборов, времени и отказов провайдера. Такой серии пока нет.

## Отдельная проба проверки решения по изображению

Это другая задача, её нельзя смешивать с отбором ID. На синтетическом **печатном**,
не рукописном изображении ученик ошибочно переводил 36 км/ч в 36 м/с и получал
360 м за 10 секунд. Параметры: temperature 0, max_tokens 2048, JSON schema,
HTTP-таймаут 120 с. Reasoning явно не задавался.

- Nemotron 3.5 Super VL: HTTP 200, 9,24 с, cost 0; прочитала условие, нашла ошибку
  перевода единиц и получила правильные 100 м.
- Dots: HTTP 400 через 1,5 с при сочетании изображения и требуемого JSON-контракта.
  Это не доказательство отсутствия vision вообще: подтверждён отказ конкретного
  запроса и маршрута.

Вывод: Nemotron VL — кандидат для следующего прототипа проверки ДЗ.
Работа с рукописью и надёжная предметная проверка этим примером не подтверждены.

## Более ранние и исключённые эксперименты

До перехода к выбору ID пробовали генерацию теории, авторских задач и проверку
в старом `RealBackend`. Временные скрипты использовали Dots и пробовали Xing с
reasoning off, max_tokens 4096, timeout 50 с; другие пробные скрипты — Dots с
2048 токенами и timeout 40 с, Nemotron VL с timeout 55 с. Наличие модели в цикле
скрипта не доказывает, что вызов к ней был выполнен: скрипт мог завершиться раньше.
Сопоставимого журнала всех этих запусков с временами и исходами нет.

Сохранилась запись отклонённого термодинамического комплекта: ответы попадали в
ученическое поле формул, терялся множитель 1000 при переводе единиц, путались
подведённая теплота и тепло за цикл, ответы расходились с решениями. Комплект
исправляли редакторски с независимым пересчётом. Запись исправлений не фиксирует
точный ID модели, поэтому приписывать все эти ошибки одной модели нельзя.
Этот опыт поддержал переход к исходным условиям и программному переносу текста.

Первую серию выбора ID на другом наборе (OpenStax) остановили для проверки
условий использования источника. В ней есть два успешных ответа (Nemotron VL и
Dots), но они **не включены** в основное сравнение Prepa. Незавершённую серию
нельзя объединять с основным тестом в одну таблицу победителей.

Каталоги `catalog.json` и `official-source-catalog.json` использовались для
проверки наличия, цен и возможностей. Запись в каталоге без результата запроса
не считается протестированной моделью.

## Где лежат доказательства

Артефакты локальные и намеренно исключены из Git: они не нужны для запуска приложения.
Здесь зафиксированы их относительные пути, чтобы воспроизвести аудит на рабочей машине:

- `local-run/output/model-comparison/prepa-benchmark/comparison-summary.json` — сводка пяти моделей и вариантов.
- `local-run/output/model-comparison/prepa-benchmark/result-*.json` — базовые запросы, время, параметры и usage.
- `local-run/output/model-comparison/prepa-benchmark/independent-audit.json` — проверка одинаковых входов и пяти PDF.
- `local-run/output/model-comparison/prepa-benchmark/liquid/preflight-incorrect-off.json` — отдельно зафиксированная ошибка настройки.
- `local-run/output/model-comparison/timeout120-retest/summary.json` — три повторные проверки при 120 с.
- `local-run/output/model-comparison/openstax-aborted/run-status.json` — остановленная ранняя серия.
- `local-run/output/homework-vision-smoke/results.json` — отдельная проба изображения.
- `local-run/output/thermodynamics-live/correction-record.json` — ошибки раннего генеративного комплекта и редакторские исправления.
- `output/main-live-report.json`, `output/magnetism-live-report.json` — поздние проверки полного процесса.

Этот документ не создаёт автоматический fallback. Текущий адаптер не переключается
сам на платные модели и не считает отсутствующий/некорректный ответ успешным.
