# PDF из проверенных материалов

## Основной путь: дословные исходные задачи

`prepa.documents.source.SourceDocuments.worksheet(TaskWorksheet)` возвращает один
`Attachment` с PDF и не принимает `LessonPackage`, выдуманную теорию или review.

```python
from prepa.documents.source import SourceDocuments

file = await SourceDocuments(engine="xelatex", font="DejaVu Serif").worksheet(worksheet)
```

Снимок `TaskWorksheet` содержит исходные `SourceTask`, текст и отдельную математику,
контрольную сумму содержания, URL/страницу и изображения `SourceImage`. PNG хранятся
base64 внутри снимка для воспроизводимой истории. Рендерер повторно валидирует
весь снимок: изменение текста, математики или байтов рисунка при старой контрольной
сумме запрещено. Он не обращается к LLM и не скачивает URL или файлы из условий.

Условия передаются в `escape_text` без переписывания, перевода и исправления чисел.
Только при отображении скрываются вводные «Впишите/Введите правильный ответ»,
«Запишите ответ» и технические маркеры `[рисунок N]`; исходный текст и SHA
остаются неизменными. Содержательные инструкции внутри условия сохраняются.
Отдельная исходная математика проходит существующий ограниченный `safe_math`.
Рисунки декодируются Pillow: PNG, совпадение SHA-256 и заявленных размеров,
не более 20 миллионов пикселей и 10 МБ на рисунок. Перед вставкой удаляются
метаданные; общий размер подготовленных уникальных изображений ограничен 20 МБ.
Декодирование выполняется в отдельном потоке. Только подготовленный код вставляет
`includegraphics` со сгенерированным SHA-именем внутри каталога компиляции;
пользовательские пути и TeX-команды в содержании не исполняются.

В ученический PDF входят название темы до четырёх слов, жирный номер, условие и исходные рисунки. Свободный запрос преподавателя в заголовок не копируется. Отдельные исходные единицы ответа оформляются как «(Ответ: Дж)», без изменения числовых данных.
Номера первой части зелёные, второй — оранжевые (по метаданным `exam_part`).
Ссылки источников сохранены в снимке для проверки происхождения, но на листе
не печатаются. Внутренние ID, ученики, ответы, теория и ДЗ не выдаются.
Задачи идут подряд с небольшим отступом: нет обязательной отдельной страницы,
семисантиметровой клетки и контейнера, удерживающего задачу целиком. Под каждой задачей — подпись «Решение:» обычным шрифтом и поле высотой 3 см с клеткой 5 мм; до начала задачи резервируется место с учётом длины условия и рисунков.
Длинные условия могут переноситься; перед началом сохраняется место на первые
строки. Рисунок ограничен высотой 38 мм и сохраняет пропорции. Применяются
тот же безопасный компилятор, ограничения и изолированные каталоги, что ниже.

`tests/test_source_documents.py` проверяет неизменность исходного текста,
экранирование, PNG/метаданные/лимиты/подмену данных и публичную выдачу.
Отдельный настоящий smoke в `output/source-renderer-smoke/` использует явно
подписанную синтетическую диаграмму: это проверка встраивания изображения,
не оригинальный рисунок ФИПИ и не доказательство полноты учебного корпуса.

## Сохранённый API генерации материалов

`prepa.documents.latex.LatexDocuments` реализует существующий `DocumentRenderer`.
Это обычный программный модуль. LaTeX и PDF не создаются отдельной моделью.

```python
from prepa.documents.latex import LatexDocuments

renderer = LatexDocuments(
    engine="xelatex",
    font="DejaVu Serif",
    output_dir="output/pdf",
    timeout_seconds=30,
)
task_file = await renderer.tasks(package.for_student(student_id))
```

Текущий пользовательский сценарий вызывает `tasks(StudentLesson)` и выдаёт один
`tasks-vN.pdf`: заголовок с темой и пронумерованные условия задач на урок.
Необязательный `title="..."` меняет только видимый заголовок и экранируется
как обычный текст; исходный комплект и его review остаются неизменными.
Крупный заголовок темы и светлая плашка с зелёным акцентом оформляют блок
задач. После каждого условия идёт бледно-зелёная сетка с клеткой 5 мм
и высотой 7 см. Обычное условие и поле решения удерживаются на одной
странице по измеренной высоте; сверхдлинное условие допускает перенос. Теория, ответы, решения, ДЗ, сведения об
ученике, уровень и длительность занятия в него не включаются. Время как физическая величина внутри условия остаётся.

Старые `teacher(LessonPackage)` и `student(StudentLesson)` сохранены как API
для будущего полного сценария, но текущий пользовательский путь их не вызывает.
Ученический вход для `tasks` и `student` создаётся через
`package.for_student(student_id)`; передача полного `LessonPackage` запрещена.

## Зависимости и запуск

В Linux нужны `texlive-xetex`, `texlive-lang-cyrillic`, `fonts-dejavu-core`.
Для macOS поддерживается Tectonic: `brew install tectonic poppler`; шрифт
`Times New Roman` уже есть в macOS. Выберите `engine="tectonic"`,
`font="Times New Roman"`. Другие значения двигателя/шрифта отклоняются.
Первое использование Tectonic скачивает стандартные пакеты TeX; прогрейте
их на вымышленном примере до запуска пользовательских заданий. Сетевой сбой
или истечение таймаута не считается успешной сборкой. Poppler нужен для
визуальной проверки, приложению для выдачи PDF он не требуется.

Бот использует этот рендерер и для реальной генерации, и для демопримера.
Для демо передайте `tasks(lesson, demo=True)`: файл называется
`DEMO-tasks-vN.pdf` и содержит видимую пометку о вымышленных заданиях. `JsonDocuments` остаётся автономным
диагностическим рендерером, а не заменой PDF в пользовательском сценарии.
Настройки движка и шрифта передаются конструктору из конфигурации приложения.

## Граница безопасности

- Структурированные входы повторно валидируются. Вход задач и ученического документа — только
  `StudentLesson`, полученный через `LessonPackage.for_student`.
- Преамбула и структура LaTeX фиксированы в коде. Обычный текст экранируется,
  включая обратную косую черту, фигурные скобки и знаки TeX.
- Математика — ограниченные выражения: дроби, корни, индексы, степени,
  греческие буквы, обычные математические операции и `\text{...}`. Кириллица в формулах (например, `м/с`) при рендеринге
  выводится через текстовый шрифт с поддержкой русского, без изменения
  сохранённого содержания и привязанного review. Запрещены
  неизвестные команды, окружения, определения, ввод/вывод, комментарии,
  изменение catcode и TeX-последовательности `^^`. TikZ используется только
  статическим шаблоном для сетки и акцента; математике LLM он недоступен. Произвольный `.tex` от LLM
  не принимается. Максимум выражения — 2000 символов и 20 уровней скобок.
- XeLaTeX запускается с `-no-shell-escape`, Tectonic — с `--untrusted`.
  Процессу не передаются API-ключи, настройки БД и произвольные TeX-переменные.
  Ограничен размер исходника, таймаут компиляции и размер PDF. При отмене
  или таймауте дочерний процесс завершается и ожидается его завершение.
- Каждая попытка имеет новый закрытый каталог внутри
  `output/pdf/<preparation_id>/v<version>/`, поэтому старая PDF не может
  выдаваться после неуспешной новой сборки. Каталоги и файлы не коммитятся.
- Ошибка компилятора, отсутствие PDF или пропавшие глифы дают `DocumentError`
  с безопасным кодом. Внешний текст и диагностические логи не пересылаются.
  Таймаут остаётся `TimeoutError`, отмена — `CancelledError`.

Allowlist и отключение shell escape не заменяют изоляцию процесса ОС.
Контейнер запускается непривилегированным пользователем; не добавляйте ему
доступ к секретам хоста. Выходные файлы могут содержать сведения об учениках:
хранение и удаление `output/` определяет оператор приложения.

## Проверки

`pytest tests/test_documents.py` выполняет автономные проверки границы TeX,
разделения материалов, таймаутов, отмены, конфигурации и ошибок компиляции.
Они не требуют установленного TeX и не обращаются в сеть.

Перед демонстрацией нужно отдельно собрать настоящий PDF на вымышленных данных,
открыть все страницы и проверить русский текст, формулы, длинные условия,
переносы и отсутствие ответов в ученической практике. Сборка PDF не подтверждает
правильность физики; содержание утверждает преподаватель по
[критериям качества](content-quality.md).
